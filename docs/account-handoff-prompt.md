# 跨 ChatGPT 账号继续提示

文档角色：**Reusable handoff prompt / 可重复使用的最小入口**

最后核验：2026-08-09

## 1. 新账号只需发送这一段

```text
继续推进 GitHub 项目 aaaycc931-droid/my-first-app。

不要从头规划，不要重复已合并工作，也不要无条件相信任何交接摘要。先以 GitHub 当前 main、开放 PR、远端分支和 Actions 为唯一实时事实来源核验，再读取仓库中的 AGENTS.md、docs/START-HERE.md 和 docs/project-process-and-account-continuity.md，按任务路由只读取必要文档。

若存在开放的当前开发 PR，先恢复它并完成 CI／审查／合并／main 验证；历史遗留 PR 不要接续。若没有开放开发 PR，再从状态矩阵与最近合并内容确定下一个尚未完成的完整切片。除硬阻塞或确需产品所有者选择外，持续推进。
```

不需要再次粘贴 17 份文档清单、旧账号的完整聊天或全部历史 PR。仓库中的入口规则是持久化上下文，GitHub 是动态事实来源。

## 2. 额度将尽时的持久化暂停协议

优先把完整切片保存到远端，而不是在聊天中写长篇交接：

1. 停止扩大范围；
2. 运行已能完成的 focused checks；
3. 把工作提交并推送到明确命名的远端分支；
4. 创建或更新 Draft PR；
5. 在 PR 描述或评论中记录精简检查点；
6. 确认本地没有仅存在于旧账号环境中的重要未提交文件。

如果代码尚不适合发布 Draft PR，交接必须明确说明它只存在于哪个工作树、哪些文件未提交，以及新账号可能无法访问。不要写成“已推送”或“CI 已通过”。

## 3. PR 检查点最小字段

```text
事实核验时间：
main HEAD：
当前分支／head SHA：
PR：编号、Draft/Ready、mergeable、behind/conflict：
已完成范围：
未完成范围：
改动文件：
本地已执行检查：
远端已确认 checks：
未执行／不能冒充的 QA：
阻塞：
下一条可直接执行的命令或动作：
```

只记录恢复工作所需的信息。提交历史、diff、checks 和评论中已有的内容用链接或 SHA 指向，不在交接中复制。

## 4. 新账号恢复顺序

1. 核验默认分支和 `main` HEAD；
2. 列出所有开放 PR，区分当前开发与历史遗留；
3. 检查 Draft、mergeability、behind/conflict 和 checks；
4. 检查有提交但没有 PR 的远端分支；
5. 检查本地工作树和未推送提交；
6. 阅读当前 PR diff 与直接相关规范；
7. 继续最近的未完成动作，不重新制定整套路线。

若交接与 GitHub 冲突，记录冲突并以 GitHub 为准。若 PR 已合并，不再重复其实现或重新开同内容 PR。
